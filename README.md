# Auto Node Simple

轻量节点安装与订阅面板，支持 VLESS-WS + Cloudflare 固定隧道、VLESS TCP Reality Vision、Hysteria2。通过一次性命令在目标服务器安装，成功回传后持久保存节点；无需 SSH 接入；新安装自动部署轻量巡检与受限自动修复，无需常驻管理代理。

## 部署

需要 Docker Compose、HTTPS 反向代理，以及自行准备的 Linux amd64 / arm64 sing-box 与 cloudflared 二进制。

```sh
git clone https://github.com/zhangx16/auto-node-simple.git
cd auto-node-simple
cp .env.example .env
mkdir -p assets data
chmod 700 data
```

编辑 `.env`，将 `PANEL_URL` 设置为自己的完整 HTTPS 面板地址，例如 `https://panel.example.com`。此地址用于安装脚本、结果回调、订阅与同源校验，必须能从目标服务器访问。

将可信来源的二进制放入 `assets/`，文件名为：

- `sing-box-amd64`
- `sing-box-arm64`
- `cloudflared-amd64`
- `cloudflared-arm64`

仓库中的 `assets/manifest.json` 记录参考构建 sing-box 1.14.3、cloudflared 2026.10.4 的 SHA-256。使用其他构建时，先核实来源与版本、验证兼容性，再运行以下命令生成对应清单。生成校验值只用于传输完整性检查，不代替来源验证。

```sh
python3 scripts/prepare_assets.py
docker compose up -d --build
curl -fsS http://127.0.0.1:18901/health
```

默认仅绑定 `127.0.0.1:18901`。通过 Nginx 等代理提供 HTTPS；首次登录使用 `data/credentials.txt` 中自动生成的管理员账号与密码。会话 Cookie 使用 Secure 属性，浏览器登录应使用 HTTPS。

反向代理及应用访问日志可能包含安装、回调、订阅路径中的访问令牌。部署时应关闭这些路径的访问日志，或进行路径脱敏。可在 Compose 中设置应用启动命令：

```yaml
command: ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "18901", "--no-access-log"]
```

## 安装节点

1. 登录面板，选择协议，填写名称、监听端口与客户端公网端口。
2. Reality / Hysteria2 必须填写服务器公网地址；分别放行或映射 TCP / UDP。监听端口与公网端口可不同。
3. Argo 仅支持固定隧道。可手动提供隧道 Token 与公开主机名，或按下一节配置自动创建。客户端地址留空使用 `www.cloudflare.com`；需要其他优选域名或 IP 时自行填写。固定隧道域名仍用于 TLS SNI 与 WebSocket Host。
4. 生成安装命令，在目标服务器以 root 执行。命令 24 小时有效，成功后不可重新下载。

支持 Alpine / Debian / Ubuntu，amd64 / arm64，systemd / OpenRC。安装成功表示本地配置与服务启动完成，不表示公网连通性已验证。Hysteria2 默认使用自签证书，导出链接启用 `insecure=1`。

同机节点共享专用 sing-box 核心，增加节点或修改监听参数会重启该核心，造成短暂中断。Argo 每个节点使用独立 cloudflared 服务。

## Cloudflare 自动创建

可选配置文件 `data/cloudflare.json` 由管理员自行创建，以下均为占位符：

```json
{
  "account_id": "YOUR_ACCOUNT_ID",
  "zone_id": "YOUR_ZONE_ID",
  "zone_name": "example.com",
  "api_token": "YOUR_CLOUDFLARE_API_TOKEN"
}
```

```sh
chmod 600 data/cloudflare.json
```

API Token 需要读取对应 Zone、管理该 Zone 的 DNS，以及管理对应账户的 Cloudflare Tunnel。面板只返回配置状态和 Zone 域名，不回显 API Token；节点只接收其自身的隧道连接 Token。

自动模式创建独立隧道、监听路由和 CNAME，域名留空时生成随机子域名；自定义域名须为该 Zone 下未被占用的一级子域名。已有 DNS 拒绝覆盖。失败时尝试清理本次资源，清理失败则保留所有权记录，供管理员处理。

安装命令过期、取消更新或删除节点均不会自动删除隧道与 DNS；退役云资源需另行处理。

## 节点管理

展开节点可复制链接、编辑和删除。Argo 默认名称后缀为 `-CF`，已有 `-cf` 后缀在启动时同步为大写；Reality 为 `-Vless`，Hysteria2 为 `-hy2`。

名称、客户端地址和公网端口保存后即时同步订阅。修改服务器监听端口或直连 SNI 时生成更新命令，需在原服务器执行；成功回传前保留原节点。更新复用节点 ID、认证信息及 Reality 身份密钥。自动隧道路由随成功回传更新，手动隧道需自行同步 Cloudflare 路由。

每个节点只允许一个未完成更新。取消更新使旧命令失效，不回滚已执行的远端更改。缺少可靠原监听资料的旧节点可能无法编辑。

删除节点需确认，会从面板及所有订阅移除，同时删除相关安装与更新记录，撤销对应命令和回调。不会卸载服务器服务，也不会删除 Cloudflare 资源及其所有权记录。

## 订阅

- 支持创建多份订阅，分别选择已安装节点；新节点需手动勾选加入。
- 提供通用 Base64、原始链接、Clash / Mihomo、sing-box 完整配置。Clash 输出 JSON，亦为合法 YAML。
- 无显式格式时根据客户端 User-Agent 识别，支持 HEAD；显式 `format` 参数优先。
- 支持编辑成员、启用、停用、删除订阅；删除订阅保留节点。
- 安装任务清理不影响已保存节点与订阅。空订阅拉取返回 409。

订阅地址自带访问凭据，无需登录即可拉取，应妥善保管。

## 数据与运维

`data/` 包含账号密码哈希、初始密码文件、会话密钥、数据库、节点连接凭据和可选的 Cloudflare 配置。数据库保存安装任务、节点、订阅及隧道所有权记录；节点配置可能包含运行凭据。请限制目录权限，按需备份，禁止上传源码仓库。

`data/`、`.env`、备份、日志、密钥文件与资产二进制均已加入忽略规则。仓库不附带账号、节点、订阅或真实 Cloudflare 配置。

节点端文件与服务：

- `/usr/local/bin/auto-node-singbox`、`/usr/local/bin/auto-node-cloudflared`
- `/usr/local/etc/auto-node-simple/configs/`：共享核心配置
- `/usr/local/etc/auto-node-simple/state/`：节点链接、证书、隧道 Token 和日志
- `auto-node-simple` 核心服务、`auto-node-<节点ID>` 隧道服务

没有远程卸载、SSH 运维或流量统计；新安装自动部署巡检与修复，可在节点管理中停用。退役节点需在服务器上清理对应服务和配置，注意共享核心仍可能供其他节点使用。

```sh
python3 -m venv .venv

pip install -r requirements.txt
DATA_DIR="$(mktemp -d)" python -m unittest discover -s tests -p 'test_*.py' -v
```

测试需要可绑定本地端口，以及 wget、flock、timeout。使用隔离数据库，覆盖登录、权限、固定隧道配置、安装回调、节点编辑与删除、订阅导出和安装器兼容性。`tests/integration_install.py` 会修改系统服务，仅供有完整测试依赖的一次性容器使用，不应在生产主机运行。


## 节点巡检与自动修复

参考 auto-argo-node 的连续失败、冷却和持久暂停策略，为 Simple 安装的协议服务提供可选修复。新节点的一条安装命令已内置巡检，协议和巡检均安装成功后回传，面板在同一事务中登记巡检凭据，无需第二条命令。已有旧节点可在「节点管理」中重装巡检；只更新面板不会远程替换已安装脚本。从旧项目导入链接的节点，必须先迁移为 Simple 协议服务，安装器不会接管旧管理脚本或旧服务。

- 节点每分钟运行一次短任务：检查本地监听；Argo 额外检查本地及固定域名的 WebSocket 握手。systemd 使用同机共享 timer，OpenRC 使用同机唯一一条 root cron；各节点串行执行，不为每个节点启动常驻进程。
- 已收到巡检的节点由面板每 5 分钟使用 assets 中校验 SHA-256 的 sing-box 客户端进行真实 HTTPS 转发。单次检测先访问 gstatic，失败再访问 Cloudflare，最多一个探测核心并行运行。探测组件或面板出站异常不作为节点修复依据。
- 本地或公网 WS 连续 3 次失败，或面板连续 2 轮转发失败，才允许重启。面板收到的同节点报告至少间隔 30 秒才计数。修复间隔至少 300 秒，同一主机共享核心也有 300 秒冷却。
- 本地故障重启原 sing-box，公网 WS 故障重启原 cloudflared；实际协议转发故障重启核心，Argo 同时重启原固定隧道。不重建云资源、不换域名、不修改 UUID、Reality 身份、端口或订阅。
- 节点出站异常、节点配置更新未完成、停用或暂停时不会发出修复授权。授权在返回前持久计数，响应丢失也计入；最近一小时最多 3 次，第三次授权后暂停后续修复，需手动「解除暂停 / 重新计数」。解除暂停不绕过冷却。
- 状态显示最后巡检、实际转发结果、已授权次数和重启结果。超过 180 秒没有报告显示巡检超时。结果在下一次报告时更新；重启服务不等于实际转发已恢复。

「停用修复」保留只读巡检，停止后续重启授权；已经发出的授权不能撤回。重新生成安装命令立即撤销旧巡检凭据，需要重新安装。删除节点同步撤销巡检凭据；远端任务保留但无法再获授权。完整退役时，systemd 执行 `systemctl disable --now auto-node-repair-<节点ID>.timer` 并删除对应 service / timer 文件；OpenRC 从 root crontab 移除带 `# simple-repair-<节点ID>` 的行，再清理此节点的 repair 子目录。不要删除其他节点共享的核心和巡检脚本。

巡检凭据保存在远端私有 curl 配置中，通过 Authorization 请求头上报；面板仅保存哈希。面板镜像关闭应用访问日志，反向代理也应禁止记录 `/repair/` 安装下载路径。真实测活只代表面板所在网络的结果；地址错误、端口封禁、隧道凭据吊销及整机断电通常需要人工处理。新节点默认安装，旧节点的巡检脚本保持兼容，不会远程重装或接管旧项目服务。


### 一体安装与巡检 v2

新下载的节点安装命令包含协议服务与巡检安装器，不再额外下载或执行第二条巡检命令。只有远端调度配置成功，结果回传才标记 `repair_installed`；面板同步持久保存节点和巡检 Token 哈希，避免未成功安装就启用修复。首次上报安排在成功回传之后。回传失败可重试原安装命令；旧版已下载脚本仍兼容，但不自动补装巡检。

节点端仍然只有协议服务常驻，不新增 Python、Node 或客户端探测核心。巡检结束即退出；同机共享一个 timer / cron、一个脚本，通过锁串行执行，重复安装会合并旧的单节点定时任务，保留其他 cron。只运行 curl、jq 和系统工具，复用已有依赖；减少重复 JSON 解析，公网 WS 成功时省略额外外网连通性请求，其他节点复用短时网络结果；协议与巡检服务定义集中写入，新安装只执行一次 systemd daemon-reload。面板探测核心仍严格串行，二进制校验改为 64 KiB 分块读取，避免每轮一次性分配整个二进制大小的内存。

已有节点更新监听参数时，会复用远端巡检凭据，并保留面板中的停用、暂停和修复计数；巡检安装失败会恢复原设置和凭据，协议安装事务也会恢复原配置。单独点击「重装巡检」仍会按原行为轮换凭据。当前巡检版本在节点详情中显示；v1 保持正常运行，需在对应服务器执行重装巡检命令后才能获得 v2 优化。

巡检 v2 完整退役：同机最后一个节点移除后，systemd 停用 `auto-node-repair.timer` 并清理对应 `.timer` / `.service`；OpenRC 移除 `# simple-repair-all` 的 cron 行。尚有节点使用时，仅移除当前节点的 repair 子目录，保留共享任务和脚本。


## 完整节点安装脚本自动升级（v3）

本项目中“安装脚本”指内置巡检的完整节点安装脚本。v3 自动升级覆盖协议核心二进制、节点服务定义、配套脚本和巡检，不只更新巡检脚本。新安装默认具备该能力。

已有 v1 / v2 需要一次引导；此前脚本只有受限重启能力，无法凭空获得下载执行新代码的能力。在对应服务器以 root 执行一次以下命令（替换为自己的面板 HTTPS 地址）：

```sh
upgrade_file=$(mktemp)
curl -fsSL https://panel.example.com/upgrade.sh -o "$upgrade_file" && sh "$upgrade_file"
rm -f "$upgrade_file"
```

引导复用本机现有节点凭据，不复制 SSH 凭据、不轮换节点 UUID、密钥或固定隧道 Token；同一服务器运行一次，共享任务会继续处理其余节点。面板的「升级安装脚本」入口也能生成一次性引导命令。无本地有效节点凭据时应先在节点管理中重新安装。

之后节点每分钟通过现有巡检通道检查面板发布的安装包指纹。指纹覆盖完整安装脚本、巡检、升级器和 assets 清单；仅当这些内容改变时升级，README 等无关改动不触发。服务端返回固定安装流程的包和 SHA-256，节点使用既有 Authorization 凭据从自己的面板获取，限制包大小、校验摘要和 Shell 语法后执行，不接受任意远程命令。升级默认要求 HTTPS（仅本机开发地址可用 HTTP）。面板发布新 assets 清单时，须先备齐对应二进制并核实摘要。

完整升级重用现有节点 ID、原始订阅 URI、端口、认证与 Reality 身份。固定隧道使用服务器上原 Token 文件，不新建隧道、不更改 DNS。调用现有安装器完成校验与服务重启，并通过原结果回传确认成功；升级会短暂重启本项目的协议服务，同机共享核心上的连接可能中断。

同机升级和人工安装通过锁串行。升级前保存核心与 cloudflared 二进制、相关配置、凭据、脚本、服务定义的私有快照；大二进制优先使用硬链接，避免常驻内存和重复复制。下载、校验、安装或启动失败时保留或尝试恢复原版本；不执行升级的远程 SSH 操作。服务器保留一份前版快照及失败现场，供必要时人工恢复。

升级状态与当前 / 目标指纹在节点详情中展示。可独立「停用自动升级」，也可对失败升级点击「重新尝试升级」；停用不能撤回已开始执行的包。相同版本失败后至少间隔一小时重试，同一指纹最多三次，之后等待人工重试或新版本。修复次数达到暂停状态、节点出站异常、存在人工配置任务时，暂缓自动升级；升级不清除修复计数或暂停状态。

以后发布须保持 v3 的上报、升级包和结果回传接口兼容。自定义配置、发行版不兼容、磁盘满或网络不可达等故障仍可能需要人工处理；自动回滚是针对可检测的安装失败，不保证任意未来程序缺陷都能自动恢复。
